# Security Policy

## Reporting a Vulnerability

Please report security vulnerabilities privately through GitHub by [creating a new security advisory](https://github.com/openfga/openfga/security/advisories/new). See GitHub's documentation on [privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) for details. Please avoid using public GitHub issues/discussions/pull requests for these.

If AI tools were used to find the vulnerability, please include the prompts or prompt history used to discover the issue in your report.

All vulnerabilities and associated information will be treated with full confidentiality. We strive to reply within 5 business days.

## Scope

The following are **in scope** for CVE assignment:

- OpenFGA server and its stable APIs

The following are **out of scope** for CVE assignment:

- **Experimental features**: Features marked as experimental are not eligible for CVE assignment. Experimental features are provided as-is, may change or be removed without notice, and do not carry the same security support guarantees as stable features.
- **Unverified scanner output**: We do not accept reports that consist solely of automated vulnerability scanner output without confirmation that the reported issue actually affects OpenFGA.

If you discover a security issue in an experimental feature, you are still encouraged to report it using the process above. We will assess the report and may address it, but it will not be assigned a CVE or treated as a formal security advisory.
